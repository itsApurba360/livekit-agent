01 Executive Summary

6
Missing / Divergent

The standalone livekit_agent repo successfully achieves deployment decoupling — it runs outside the Frappe bench, talks to ERPNext via REST, ships with Docker/uv, and includes a browser sandbox. Core verification mechanics (OTP, DTMF, Python-level PDF gate, in-place prompt mutation) are in place.

Biggest architectural divergence: restructuring.md proposes a hybrid gatekeeper where registered customers can query balances/orders by voice without OTP, and OTP is only required for WhatsApp PDF delivery. The current code requires OTP for all customer data tools — matching the older integrated bench agent, not the new spec.
Second major gap: The spec defines dedicated Frappe whitelisted endpoints (check_caller_type, send_otp_whatsapp, get_agent_config, log_call_completion). None exist on the Frappe side yet; the worker uses generic REST resource APIs and direct watoolx methods instead.

04 Component Responsibilities

Module Responsibility Key Functions
agent.py Orchestrates every call: metadata parsing, caller ID extraction, agent selection, prompt compilation, session lifecycle, DTMF OTP handler, verification callback entrypoint(), get_compiled_prompt(), on_verification_success()
frappe_client.py Token-authenticated HTTP to Frappe. Generic CRUD on doctypes. Client-side caller matching across Customer, Contact Phone, Lead tables. WhatsApp via watoolx. lookup_caller(), get_resource_list(), send_whatsapp_message()
agent_tools.py LLM-callable tools. Enforces is_verified gate on queries + PDF. Generates OTP locally, verifies voice/DTMF input. 10 function tools: sales orders, invoices, OTP, PDF, search
agent_config.json Static prompts, greetings, provider/model/voice. No remote fetch or cache. Support (Kavya) + Sales (Nandini) personas
web_ui_server.py Dev-only: issues LiveKit JWT with agent dispatch metadata for browser testing. POST /api/token

05 Security & Verification Model

restructuring.md (Target)

  • Registered caller → voice queries without OTP
  • WhatsApp PDF delivery → OTP required
  • Python flag is_verified gates PDF tool only
  • Dedicated send_otp_whatsapp Frappe endpoint
  • In-place system prompt mutation (no history append)

livekit_agent (Current)

  • All customer data tools check is_verified
  • Prompt rules force OTP before any balance/order query
  • PDF also gated by is_verified ✓
  • OTP sent via direct watoolx REST method
  • In-place prompt swap ✓ + extra one-time system note on verify

06 Comprehensive Gap Analysis

Done Fully implemented Partial Started but incomplete or diverges Missing Not implemented Extra Beyond spec (bonus)
Area restructuring.md Requirement Current State Status Impact / Notes
1. Separate deployment Worker outside Frappe bench; isolated deps; containerized Standalone repo, pyproject.toml, Dockerfile, uv, no import frappe Done Core migration goal achieved. Deploy via Docploy with outbound WebSocket only.
2. REST vs ORM All data access via secured REST, not direct DB FrappeRestClient uses /api/resource/* + watoolx methods Partial Works but uses broad resource API (least-privilege weaker than dedicated endpoints). API key needs wide read permissions.
3. check_caller_type POST support_360ithub.livekit.check_caller_type Client-side lookup_caller() with multiple REST list queries Partial Functionally similar output. No server-side endpoint; logic duplicated in worker; harder to optimize/cache.
4. Hybrid gatekeeper Voice queries for matched customers without OTP; OTP only for WhatsApp PDF All query tools + prompts require OTP first Missing Critical divergence. Worse UX (OTP for "what's my balance?"). Matches old integrated agent, not new spec.
5. send_otp_whatsapp Dedicated Frappe endpoint receives phone + OTP Worker generates OTP locally; calls watoolx send_custom_whatsapp_message directly Partial Works end-to-end. OTP generation on worker side (not Frappe). No centralized OTP audit on server.
6. Python PDF gate send_pdf_whatsapp checks is_verified regardless of LLM Implemented in agent_tools.py Done Prompt injection cannot bypass PDF send. Aligns with spec.
7. DTMF verification Keypad entry as alternate OTP path sip_dtmf_received handler in agent.py Done 4-digit buffer, triggers same on_verification_success callback.
8. In-place prompt mutation Recompile CORE_PROMPT at index 0; don't rely on appended system messages get_compiled_prompt(is_verified=True) swaps first system message Partial Also appends one-time [System Note: Verification successful...] — spec prefers mutation only.
9. Agent routing Customer → Kavya (Support); Lead/Unknown → Nandini (Sales) caller_status == "Customer" → Support else Sales Done Matches spec Phase 1 identity routing.
10. get_agent_config Fetch model/voice/greeting/custom_instructions from Frappe with TTL cache Static agent_config.json + env API keys only Missing Business users can't change promos/models from Frappe Admin without redeploy.
11. Hybrid config model Core safety in Git; business overrides from Frappe Entire prompt + model config in JSON file Partial Safety rules are in code (DEFAULT_SUPPORT_*_RULES) but greetings/model not dynamic.
12. On-demand tool data Don't preload invoice lists into prompt; use tools at runtime Tools fetch live data; prompt only adds customer_id context Done Aligns with spec section 6B.
13. log_call_completion Create/update Support Call Log with transcript on call end Not implemented in standalone worker Missing Integrated agent auto-creates Support Call Log on inbound; standalone has no call logging lifecycle.
14. Outbound dialing Implied in production (sales follow-up calls) Comment mentions outbound; no dial-out logic. Relies on Frappe initiate_agent_outbound_call in integrated app Missing Outbound room detection exists (agent_call_*) but no SIP dial, no call log creation, no metadata from Frappe.
15. Call transfer / recording Not in restructuring doc Integrated app has Vobiz sync, recording download — absent here Missing Regression vs integrated deployment for ops features.
16. Web UI sandbox Not specified web_ui_server.py + polished static UI Extra Valuable for local prompt/tool testing without PSTN.
17. Test coverage Not specified Unit tests + optional live Frappe integration tests Extra tests/test_agent_tools.py, test_frappe_connection.py, etc.
18. Frappe endpoint module New whitelisted methods under support_360ithub.livekit Existing module has outbound worker control, Vobiz sync — not the 4 new endpoints Missing Both worker and Frappe app need coordinated API layer work.

Quick win — Hybrid gatekeeper
Remove is_verified checks from read-only query tools when customer_id is linked to the inbound phone match. Keep gate only on send_pdf_whatsapp. Update DEFAULT_SUPPORT_UNVERIFIED_RULES to only mention OTP for WhatsApp delivery.
Coordinated change — Frappe API layer
Add the four whitelisted methods in support_360ithub/livekit.py, then refactor frappe_client.py to call them instead of raw resource endpoints. Enables least-privilege API keys and server-side OTP logging.
